# Dashboard and transaction UI changes — 23 October 2026

Issues: #92 (transaction sources), #93 (mobile and admin dashboards).
Integration path: `feat/ui-polish` → `staging`. The live deployment and released
1.4.0+14 APK are separate from this change.

## Behaviour

- Keep the existing green/mint Material theme and navigation. Dashboard and
  Analytics summaries use compact cards, with a single column for narrow layouts
  or large text. Dashboard links open Analytics and Budgets.
- Both analytics endpoints return `expense_categories` for the same authenticated
  owner, reporting interval and reversal filters as their expense totals. Category
  bars show amounts in KES; smaller categories are grouped without discarding their
  amounts. An older response without this field displays an unavailable message.
- Budget cards show spent, limit and remaining/exceeded amounts. Existing cash-flow
  details and edit/delete actions remain available under More budget details.
  Category budgets remain individual limits rather than a new summed total.
- Forecasts use a plain estimate panel and labelled estimate/recorded bars.
  Missing actuals remain pending. Recent saved history shows one latest comparison
  per completed week, with loading, empty, failure and retry states. History
  readiness is not predictive accuracy.
- Transaction dates have a small source icon: message for M-PESA SMS, pencil for
  manual entries, document for CSV and headset for support. Tapping it explains the
  source. Unknown or missing sources are unavailable rather than assumed manual.
  Editing an imported entry does not change its recorded source. Reversed status
  stays separate and excluded from financial totals.
- Admin overview has four main metrics, expandable additional totals, cash flow,
  seven Nairobi calendar days of sign-in event counts and new-account counts, and
  the existing management links and tables. Sign-in events exclude registration,
  include repeat sign-ins, and do not imply online presence. Today is partial.
- Model evidence remains artifact-matched. Precision/recall/F1 bars supplement the
  stored numeric results, limitations and source identities. Missing evidence is
  not estimated. Model files, thresholds, seeds and evaluation metrics are unchanged.

Charts use existing Flutter widgets/custom painting and the admin canvas; no new
charting library, framework, SDK or database migration is required.

Device: disposable AVD `SpendlySmsFinal_20261023`, `emulator-5564`, API 36.
The application checks the separate `.acceptance` package before testing. The
loopback API on port 5057 uses in-memory SQLite and the saved portable model;
the administrator fixture uses a separate in-memory target on port 5058.

The final native run passed one suite in 59 seconds after installation, with the
opt-in CSV picker test skipped.
It exercised local API/storage/account isolation, partial insights, category
parsing, the manual source explanation, real portable inference and a 13-page tour
at 200% text. The completed-forecast comparison page used an explicit synthetic UI
fixture; it is not an additional model evaluation.

An earlier run emitted a failed attempt to uninstall the base package on the
disposable emulator; the final run did not repeat this warning. Cleanup checks the
actual `.acceptance` package explicitly. No personal phone, inbox, OAuth account or hosted financial records are
used by these checks. This is not a fresh native SMS-inbox or OAuth acceptance run.
