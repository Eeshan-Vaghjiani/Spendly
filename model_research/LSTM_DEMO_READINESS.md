## Input contract and preserved equations

`category_lstm_features.py` preserves the reviewed notebook's trained feature
equations exactly, generated by `build_category_feature_source.py`. The wrapper
does not change weights, transforms, category order or the notebook's nonnegative
output clipping. It repairs input-boundary handling for evaluation:

- Explicit one-household identity, offset-aware dates normalized to Nairobi.
- Explicit Monday-start observation and target boundaries; target not after as-of.
- At least26 complete covered weeks and complete-history attestation.
- Preserve all covered weeks, including confirmed zero-spend edges. Unknown
  coverage is rejected rather than silently filled with zeros.
- Include all available past history for long-lag/rolling features, then take the
  final26 feature vectors. Seven-month history does not supply52-week references.
- Reject incomplete/current target-week rows, invalid values, duplicates and
  unknown expense categories. Income never falls back to being expenditure.

Callers must provide all transactions within their attested interval; the adapter
cannot detect omitted records. Coverage attestation is not confidence in a forecast.
Category mappings and historical availability must be reviewed before Wasaa use.

## Actual checks and findings

Seven synthetic/notebook tests and10 subtests passed. Actual model runs covered three
generated household histories of26,52,80 weeks (27 category outputs):

- Correct model/scaler shape and finite statistics; all four hashes verified.
- Repeated load gives exactly identical outputs.
- A second fresh CPU process reproduced the same outputs exactly.
- Batch versus one-at-a-time maximum absolute difference **KES3.8125**. This
  passed the explicit tolerance `atol=.02, rtol=1e-5` because the affected forecast
  was very large. This is **not** a sub-cent absolute parity claim. Fix batch policy
  before comparing results near a decision boundary.
- First startup attempt timed out before inference output; a longer startup limit
  completed. No leftover Python process from that attempt was observed.

### Sparse-history warning from observed outputs

Fixtures contain Food/Transport and periodic Rent, with no Utilities expenses.
Utilities forecasts were approximately KES101,163, KES670,350 and KES6,416 for
the26/52/80-week fixtures. These are synthetic probes without next-week truth;
they demonstrate implausible extrapolation risk, not measured external error or
proof of a particular cause. No caps, category suppression or weights were added
after observing the result. Preserve such cases in external evaluation and report
zero-history categories and extreme predictions separately.

The adapter is therefore ready to **measure** transfer, not to assure good advice
or automatically use the category model in production.
